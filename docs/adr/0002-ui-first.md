# ADR 0002 — الواجهات أولا (مسار "ب")

- **الحالة:** معتمد (2026-09-30، طلب صاحب المشروع "ابدأ بناء الواجهات" بعد عرض المسارين في `docs/UI-READINESS.md` §5)
- **السياق:** الخطة (`docs/PLAN.md`) ترتب العمل: المحرك (3–4) ← قاعدة البيانات (5) ← أساس الويب (6) ← الشاشات (7–8). صاحب المشروع اختار رؤية المنتج أولا.

## القرار

كل شاشات SPEC §7 (جدول الحصص والحياة المدرسية ولوحة صاحب المنصة) تُبنى الآن في `apps/web` فوق طبقة **مؤقتة**:

| المؤقت | الموضع | يُعوَّض بـ |
|---|---|---|
| مخزن في المتصفح (`localStorage`، مفتاح `hissas-web-v1`)، مدرسة لكل slug تحت `/s/[school]` | `apps/web/lib/store.ts`، `lib/school.tsx` | قاعدة البيانات عبر `tenantDb(schoolId)` (الخطوة 5)، والمدرسة من النطاق الفرعي + العضوية (الخطوة 6) |
| المحرك المحلي: نقل حرفي لمحرك النموذج الأولي (جشع + تلدين + LNS، نفس الأوزان) في Web Worker | `packages/shared/src/engine`، `apps/web/lib/solver.worker.ts` | `/solve` و`/repair` على CP-SAT (الخطوتان 3–4) بنفس العقد |
| بدون مصادقة ولا أدوار | — | Auth.js + RBAC (الخطوة 6) |
| الوثائق والشعار: الاسم فقط / رابط data | `SchoolState.docs`، `SchoolMeta.logo` | S3 خاص بروابط موقّعة تحت `{school_id}/` |
| شبكة الأساتذة: أزرار محاكاة كما في النموذج الأولي | `timetable/network` | الحجز بالتداخل الزمني (ADR 0001 §2) بعد الخطوة 5 |
| النصوص بالعربية مباشرة | كل الشاشات | next-intl (العربية والفرنسية) |

**ما هو نهائي:** كل منطق الشاشات يأتي من `packages/shared` (منقول من النموذج الأولي ومحمي بالمطابقة)، والشاشات تستهلكه فقط. تغيير طبقة البيانات لا يمس المنطق.

## القرارات المعلقة (السلوك الحالي = النموذج الأولي، معلَّم في الكود بـ "[قرار معلق]")

1. التوليد يطبَّق مباشرة ويرسل "نُشر جدول الحصص" (لا مسودة ثم نشر) — `apps/web/lib/generate.ts`.
2. ربط التلميذ بالولي **بالاسم** — `packages/shared/src/life/actions.ts` (`addStudent`).
3. مكتبة Excel: **ExcelJS** مؤقتا، محصورة في ملف واحد `apps/web/lib/xlsx.ts` (القراءة والكتابة).
4. غياب الأستاذ على **يوم الأسبوع** لا التاريخ — `timetable/absences`.
5. صيغة رقم التسجيل `رقم/سنة`، وحد التأخر غير مستعمل.

## العواقب

- إعادة عمل محدودة في طبقة البيانات (المخزن ← استدعاءات الخادم) عند الخطوات 5–6.
- اختبارات Playwright (`apps/web/e2e`) تحمي سلوك الشاشات وتبقى صالحة بعد تغيير الطبقة.
- لا بيانات حقيقية: كل شيء في متصفح المستعمل، والبيانات التجريبية فقط.
